# RAG 概览

RAG（Retrieval-Augmented Generation，检索增强生成）是把外部知识通过检索注入到大模型上下文里的做法。
它解决的是一个具体问题：大模型的参数里只有训练语料的统计规律，不知道你的私有文档，面对私有问题
只能靠"编"或者"我不知道"，而前者概率高得多。

## 两个阶段
- **写入侧（离线）**：把原始文档切分成合适大小的文本块，用 embedding 模型逐块转向量，存进向量库。
  同时把块级的元数据（文件名、块序号、内容哈希）一起存下来，后面按文档删除和溯源都靠它。
- **读取侧（在线）**：把用户问题也转向量，去向量库找最相近的若干段原文，拼进 prompt 交给大模型生成。

## 为什么不是把整篇文档塞进 prompt
一是上下文有长度上限，二是无关内容会稀释注意力，三是成本随 token 线性上升。检索的作用是
在回答之前先把候选范围从"全库"缩到"最相关的几段"。

## 常见的失败模式
1. **检索没召回**：资料里有答案，但没被排进前几。混合检索和重排就是在治这个。
2. **召回了噪声**：资料里本来没有答案，但相似度阈值太松，硬塞了几段无关内容，模型据此硬答。
3. **切块不合理**：关键句被切断，两段各拿一半，谁也答不出。
4. **有依据但模型不看**：检索结果正确，模型还是按自己的记忆回答。这要靠 prompt 约束和引用溯源来治。
