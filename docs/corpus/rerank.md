# 重排序 Rerank

## 双塔与交叉编码
粗召回用的 embedding 是双塔：问题和文档各自独立编码，编码时彼此没见过面，只能捕捉粗粒度相似。
重排用的是交叉编码器（cross-encoder）：把 query 和 document 拼在一起送进模型，注意力机制能让它逐字对比，精度高得多。

## 代价
交叉编码器每条候选都要跑一次完整推理，没法像双塔那样预先算好。所以只能对粗召回出来的几十条候选做，
不能对全库做。这就是业界通用的两段式：便宜的模型把范围从百万缩到几十，贵的模型把这几十条排准。

## 接口约定
硅基流动的 rerank 接口是 POST /v1/rerank，请求体包含 model、query、documents 数组、top_n、return_documents，
响应是 results 数组，每项含 index 和 relevance_score。index 是 documents 数组里的下标，
靠它把分数映射回原候选——千万别按文档内容去匹配，候选之间内容可能高度相似，按内容找会张冠李戴。

## 一个反直觉的点
重排模型只负责排序，不负责拒答。它会把不相关片段的分压到 0.001，但只要不设阈值，这些片段照样会被返回。
所以"拒答"这件事必须在别的地方兜住，不能指望重排。
